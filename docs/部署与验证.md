# 飞印（FlyPrint）部署与验证

| 属性 | 说明 |
|------|------|
| 文档类型 | 部署、配置与验证指南 |
| 适用产品 | 飞印云打印平台（Cloud + Edge） |
| 部署形态 | **公网**（一套 Cloud，多 Edge 直连）与 **局域网**（校内 / 单机 Compose） |
| 本阶段入口 | 公网可先仅 **HTTP / 80**；正式环境推荐再上 HTTPS |

本文说明如何安装 Cloud / Edge，并完成最小闭环验证。

**版本说明：** Edge 以安装包版本为准；Cloud 以当前 Compose / 发布包镜像为准。

---

## 1. 部署总览

### 1.1 两种形态

| 形态 | 适用 | 入口 | Edge 怎么连 |
|------|------|------|-------------|
| **公网** | 学校正式 / 试运行；两校区等多点 | 唯一 nginx 对外 **:80**（可再经 SLB 上 443） | 各校区 Edge **出站直连**公网 Cloud |
| **局域网** | 校内演示、开发联调 | Compose 默认 **:8012**（根路径） | Edge 与手机同网访问该入口 |

推荐顺序：

1. 定形态（公网或局域网），准备地址与密钥  
2. 部署 Cloud  
3. 安装 Edge，配置 `cloud.base_url`  
4. 激活节点并设置默认 IPP 打印机  
5. 官方扫码打印闭环（可选再联调第三方 / Demo）

### 1.2 强制要求

| 要求 | 说明 |
|------|------|
| 密钥 | 公网不得继续使用演示默认管理员密码与各类密钥 |
| 可达性 | Edge 的 `cloud.base_url` 须为手机与一体机均可访问；禁止对手机链路使用 `localhost` |
| 路径一致 | **公网子路径**部署时，`cloud.base_url` 须带 API 前缀（如 `http://域名/fly-print-api`） |
| HTTPS | 正式对外推荐 HTTPS；不得依赖「`https://localhost` + 出码改写局域网 IP」 |
| 数据 | 禁止 `docker compose down -v`（会删卷） |

## 2. 部署前准备

### 2.1 地址与端口

| 形态 | Cloud 入口 | Edge `cloud.base_url` 示例 | Admin |
|------|------------|---------------------------|-------|
| 公网子路径（发布包） | 主机 **:80** | `http://fly-print.click/fly-print-api` | `http://fly-print.click/fly-print-web` |
| 局域网根路径 | 主机 **:8012** | `http://<局域网IP>:8012` | 同左（根路径） |

公网发布包路径约定：

| 路径 | 用途 |
|------|------|
| `/fly-print-web/` | 管理端 + 官方上传页 |
| `/fly-print-api/` | API / Auth / entry / Edge WS |
| `/integration-demo/` | 可选第三方演示 |
| `/entry`、`/upload` | 根路径兼容（重定向到上述前缀） |

### 2.2 环境变量（必核）

以 `.env.example` 或发布包 `.env.template` 为模板。公网子路径尤须核：

| 变量 | 用途 | 公网子路径示例 |
|------|------|----------------|
| `EXTERNAL_API_URL` | 对外 API 根 | `http://fly-print.click/fly-print-api` 或 `https://…` |
| `ADMIN_CONSOLE_URL` | 管理端对外 URL | `http://fly-print.click/fly-print-web` |
| `ALLOWED_ORIGINS` | CORS | 须包含浏览器实际 Origin（`http://` 与 `https://` 分开写） |
| `OAUTH2_REDIRECT_URI` | OAuth 回调 | `…/fly-print-api/auth/callback` |
| `TRUSTED_PROXY_CIDRS` | 可信反代网段 | 经 Docker nginx 时常用 `172.16.0.0/12` 等 |
| `DEFAULT_ADMIN_PASSWORD` 等密钥 | 首次管理员与签名密钥 | 公网必须为强随机值 |
| `REACT_APP_*` / `PUBLIC_URL` | **仅构建 Admin 镜像时生效** | `/fly-print-web`、`/fly-print-api/api/v1`、`/fly-print-api/auth` |

说明：

- 子路径 Admin 必须在 **build 镜像时**注入 `PUBLIC_URL` / `REACT_APP_BASENAME` 等；只改运行中 `.env` 不会重写已构建的前端静态资源。  
- 域名切换与发布包配置由交付方在受控工具链中完成；`ALLOWED_ORIGINS` 建议同时保留 http 与 https Origin，直至全面切换 HTTPS。  
- Edge 的 `cloud.base_url` **不是** `.env` 项，在一体机本机管理页配置。

### 2.3 Edge

| 项 | 说明 |
|----|------|
| 安装包 | Windows 安装程序 |
| `cloud.base_url` | 与手机打开的 Cloud **API 根**一致（公网子路径须含 `/fly-print-api`） |
| 浏览器 | 已安装 Microsoft Edge |
| 打印机 | 网络可达、支持 IPP；设为默认 |
| 本机管理 | 默认 `http://127.0.0.1:7860` |

### 2.4 账号

| 用途 | 说明 |
|------|------|
| Cloud 管理端 | 公网部署后使用强密码；初始凭证通过受控交付材料或值班人员提供 |
| Edge 本机管理 | 默认仅本机回环，无独立本机管理员密码 |

## 3. 公网部署（受控发布包 · 仅 80）

适用：学校试运行 / 双校区 Edge 直连公网 Cloud。发布包与内部安装说明由交付方通过受控渠道提供；本仓不包含打包、安装或凭证脚本。

### 3.1 本机打包（性能较好的机器）

本地打包由交付方在受控构建环境执行，需构建 `api` / `admin-console-builder` / `integration-demo`，并确保 Admin 使用 `/fly-print-web` 前缀构建。

### 3.2 服务器安装

服务器安装由交付方按受控发布说明执行。安装前确认发布包来源、域名/IP、强随机密钥、管理员初始凭证和回滚联系人；安装后按本章检查单验证，不要把凭证或内部安装脚本放入公开仓库。

要点：

- **不要** `--build`；只 `docker load` + `compose up`  
- nginx 映射 **`80:80`**；库 / Redis / MinIO **不对公网暴露**  
- 安全组至少放行 **80**（运维另开 22）  
- **禁止** `docker compose down -v`

### 3.3 安装 Edge 并激活

1. 安装 Edge 安装包  
2. 本机管理页设置 `cloud.base_url = http://fly-print.click/fly-print-api`  
3. Cloud Admin 生成激活码 → Edge 激活 → 确认 online  
4. 发现 IPP 打印机并设默认  

HTTP 下 WebSocket 为 **ws**；若日后面向 HTTPS，自动为 **wss**。

### 3.4 官方扫码打印（主验证）

1. Edge 出示二维码  
2. 手机扫码 → 官方打印 → 上传  
3. 一体机预览并确认  
4. Admin 任务为 **已完成（`completed`）**  

### 3.5 第三方 / Demo（可选）

公网 Demo 的 `entry_url` 使用 `http://fly-print.click/integration-demo/entry`；`callback_base_url` 仍为 `http://integration-demo:8080`。接入编码、密钥粘贴与 Provider 字段按对接契约填写（Demo 的 `code` 固定为 `livacloud-demo`）。

## 4. 局域网部署

适用于校内演示或开发联调（根路径，默认口 **8012**）：

```powershell
cd fly-print-cloud
docker compose up --build -d
```

| 项 | 值 |
|----|-----|
| 入口 | `http://<Cloud局域网IP>:8012` |
| Edge `cloud.base_url` | 与上相同（**无** `/fly-print-api` 前缀） |
| Admin | 同入口根路径 |
| Demo 入口 | `http://<IP>:8012/integration-demo/entry` |

- 演示默认管理员仅用于临时内网；进公网必须改密与轮换密钥  
- 停止并保留数据：`docker compose down`（不要 `-v`）  
- 可不启 Demo：`docker compose up --build -d --scale integration-demo=0`

### 4.1 同机第三方演示联调（局域网）

| 配置项 | 值 |
|--------|-----|
| `code` | **`livacloud-demo`**（Demo 程序固定；非平台只允许该码） |
| `entry_url` | `http://<局域网IP>:8012/integration-demo/entry` |
| `callback_base_url` | `http://integration-demo:8080` |
| `allowed_file_hosts` | `integration-demo`；`allow_private_file_hosts=true` |
| `allowed_ip_cidrs` | `172.16.0.0/12` |

创建后将入站/出站 HMAC 粘贴到 `/integration-demo/setup`。

### 4.2 双校区形态（简述）

**一套公网 Cloud + 每校区一台 Edge 直连。** Cloud 由统一维护；各校区仅部署一体机与打印机。

## 5. 验证检查单

**Cloud**

- [ ] 管理端可登录；公网已改默认密码  
- [ ] 健康检查正常（公网：`/fly-print-api/api/v1/health`；局域网：`/api/v1/health`）  
- [ ] 数据库 / 缓存 / 对象存储控制口未对公网暴露  
- [ ] （当前阶段）HTTP/80 可验收；**HTTPS 另标是否已验**

**Edge**

- [ ] 节点 online；默认 IPP 可用  
- [ ] `cloud.base_url` 正确（公网子路径含 `/fly-print-api`；非 localhost）

**业务闭环**

- [ ] 官方扫码打印一单至 `completed`  
- [ ] （可选）`livacloud-demo` 一单至完成  

**现场**

- [ ] 第 6 节系统手势与误触相关项按需配置

## 6. 一体机操作系统建议

安装包可全屏 kiosk，**不能**替代 OS 手势策略。建议收紧：边缘滑动 / 多指手势、任务栏与通知、休眠与营业时段更新、非管理员营业账户、固定 IP 或 DHCP 保留。手机须能访问 Cloud，无需访问 Edge 回环。

## 7. 常见问题

| 现象 | 排查要点 |
|------|----------|
| 公网 curl 域名超时、本机 127.0.0.1 正常 | 阿里云 ECS 上**自访公网 IP/域名**常失败；请用外网机器测 |
| 登录 403 / origin not allowed | `ALLOWED_ORIGINS` 是否包含浏览器实际 Origin（http 与 https 不同） |
| 扫码 404 | `cloud.base_url` 是否带 `/fly-print-api`；nginx 是否有 `/entry`→API、`/upload`→Web 重定向 |
| 点「官方打印」后 404 | 是否缺少 `location /upload` → `/fly-print-web/upload` |
| Edge 离线 / 约 60s 掉线 | 出站是否放行；若经 SLB，须支持 WebSocket 且空闲超时 >60s |
| 有预览无出纸 | Edge↔打印机 IPP、默认机、耗材（非 Cloud 直连） |
| 第三方 API 403 | Provider `allowed_ip_cidrs`；`TRUSTED_PROXY_CIDRS` |
| 数据丢失 | 是否误用 `docker compose down -v` |

日志示例：`docker compose logs -f api nginx`
