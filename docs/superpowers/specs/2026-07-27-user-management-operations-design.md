# 用户管理运维能力设计

## 目标

修复 Admin 用户管理中的停用错误，并补齐停用/恢复、物理删除、用户名编辑以及面向运维的筛选和排序能力。继续复用现有 `users` 表、builtin JWT 和 Admin 权限边界。

## 范围与约束

- 邮箱是登录唯一标识；用户名是独立的可编辑展示字段。
- 用户停用后不能登录，但仍应出现在用户管理列表中，并可由管理员恢复。
- 当前登录管理员不能删除自己。
- 不删除现有 `users` 表、Admin 用户管理、builtin JWT 或 OAuth2 用户同步逻辑。
- 不删除用户上传文件；本次删除只处理用户记录、打印任务和打印任务告警。
- 不新增完整 RBAC，不改变未来 SSO、丽娃文件接口或 HMAC 逻辑。

## 后端设计

### 用户查询

用户管理列表查询不再默认过滤 `inactive` 用户。Repository 提供包含启用和停用用户的列表结果，并支持：

- 关键字：匹配用户 ID、用户名、邮箱；
- 角色筛选；
- 状态筛选；
- 分页；
- 允许列表内的字段排序，排序方向由白名单参数控制。

按用户 ID 查询管理详情时不限制 `status = 'active'`，以便管理员恢复停用账号和对停用账号进行删除操作。登录使用的邮箱查询仍只返回 active 用户，确保停用账号不能获取新 JWT。

### 打印任务中的打印人

打印任务 API 在保留现有 `user_id`、`user_name` 的基础上返回 `user_email`。对官方账号任务，通过 `print_jobs.user_id` 与 `users.id` 关联读取当前邮箱和用户名；对历史第三方任务或已无法匹配用户的任务，保留已有任务快照字段，不阻塞任务列表。

打印任务列表支持按稳定用户 ID 和邮箱筛选。用户管理页与打印任务页使用稳定的用户 ID 作为跳转条件，同时在页面上展示邮箱筛选值，避免用户改邮箱后历史跳转依赖旧邮箱文本。打印任务页的打印人邮箱和名称都可跳回用户管理页；用户管理页的邮箱可跳转到该用户的打印任务列表。

### 更新与停用接口

现有更新接口只接收并更新邮箱、用户名和角色，不再接收状态字段。邮箱继续做规范化、唯一性和格式校验；用户名继续做格式和唯一性校验。

新增用户启用状态接口：

```text
PATCH /api/v1/admin/users/:id/enabled
Body: { "enabled": true | false }
```

`enabled=true` 写入 `status=active`，`enabled=false` 写入 `status=inactive`。接口只允许管理员调用，并返回更新后的用户信息。停用操作不删除打印任务或文件。

### 删除事务

```text
DELETE /api/v1/admin/users/:id
```

删除流程在一个数据库事务中完成：

1. 锁定目标用户并允许读取任意状态；
2. 获取当前认证上下文中的 `external_id` 作为当前管理员 ID；
3. 目标用户与当前管理员相同时拒绝；
4. 查询该用户状态为 `pending`、`dispatched`、`processing` 的打印任务；
5. 若存在活动任务，返回冲突错误，不修改任何数据；
6. 删除该用户的打印任务告警；
7. 删除该用户的全部打印任务；
8. 删除用户记录并提交事务。

删除失败或中途出错时回滚整个事务。活动任务状态沿用现有打印任务状态定义；不将 `completed`、`failed`、`canceled`、`unconfirmed` 视为活动任务。

### 错误响应

- 未找到用户：`用户不存在`；
- 当前管理员尝试删除自己：`不能删除自己`；
- 存在活动打印任务：`用户存在打印中的任务，无法删除`；
- 无效启用状态、邮箱或用户名：使用现有参数错误响应；
- 非管理员访问：继续由现有 scope 中间件拒绝。

## 前端设计

Admin 用户页面继续使用 Ant Design，复用节点、打印机和运维联系人页面已有交互模式。

### 列表

列表展示邮箱、用户名、角色、最后登录和操作。状态不再作为独立列，替换为“启用”列中的 `Switch`。列表默认展示 active 与 inactive 用户。

打印任务列表新增“打印人”列：第一行显示打印人邮箱，第二行以灰色小字显示打印人名称。邮箱可点击跳转用户管理并带上用户筛选；无法匹配用户的历史任务只展示已有任务快照，不生成虚假用户链接。

顶部增加：

- 用户 ID/用户名/邮箱关键字搜索；
- 角色筛选；
- 启用状态筛选。

表格提供邮箱、用户名、角色、启用状态、最后登录和创建时间的排序能力；分页继续保留。

### 编辑

- 用户名列单击进入行内编辑；
- 输入框不额外显示旧名或技术名；
- 回车或保存按钮提交；
- 点击编辑区域外取消，不提交修改；
- 邮箱和角色仍通过编辑表单修改；
- 编辑表单移除状态选择；
- 新建用户要求邮箱、用户名、密码和角色。

### 停用与删除

- `Switch` 直接调用启用状态接口；
- 删除按钮使用危险样式和二次确认；
- 删除成功后刷新当前列表；
- 删除被活动任务阻止时展示后端稳定中文原因；
- 每个 Toggle 请求独立显示 loading，避免重复提交。

## 测试设计

### Go

- 管理列表包含 active 和 inactive 用户；
- 用户关键字、角色、状态、分页和白名单排序查询；
- 用户名修改与用户名唯一性；
- 邮箱修改与邮箱唯一性；
- 启用接口正确切换 active/inactive；
- 删除从 `external_id` 读取当前管理员身份；
- 删除自己被拒绝；
- 存在 pending/dispatched/processing 任务时删除被拒绝且数据不变；
- 没有活动任务时打印任务告警、打印任务和用户记录在同一事务内删除；
- 删除事务失败时回滚；
- 停用用户不能通过邮箱登录。

### React

- 用户名单击进入行内编辑，点击外部取消；
- 用户名保存提交独立字段；
- 状态列不再出现，Switch 显示并切换启用状态；
- 删除按钮发送 DELETE 并显示服务端错误；
- 关键字、角色、启用状态筛选和表格排序生效；
- 编辑表单不包含状态字段，邮箱和用户名显示为不同字段。

### 打印任务与用户互跳测试

- 打印任务列表返回 `user_email` 和 `user_name`；
- 官方用户任务按用户 ID 正确关联当前邮箱和用户名；
- 打印任务按用户 ID、用户邮箱筛选；
- 用户管理邮箱跳转到该用户打印任务筛选；
- 打印任务邮箱跳转到用户管理筛选；
- 用户不存在或第三方历史任务不生成错误用户链接。

## 不采用的方案

- 不把删除继续伪装成停用；
- 不在前端自行判断活动打印任务后再删除，避免并发竞态；
- 不用客户端缓存替代后端事务；
- 不级联删除用户文件；
- 不新增独立用户状态表或新的认证体系。
