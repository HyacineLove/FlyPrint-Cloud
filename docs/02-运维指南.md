# 飞印运维指南

本指南按四方角色说明职责与时机。

**推荐协作方式：** 学校管理侧使用管理网站随时监控；发现问题后派运维到场；运维每日另做一次轻量巡检。用户只使用打印，不承担运维。疑似产品缺陷时再升级开发方。

---

## 1. 四方角色

| 角色 | 是谁 | 主要用什么 | 核心职责 |
|------|------|------------|----------|
| **用户** | 师生等使用人 | 手机 + 一体机大屏 | 扫码、上传、预览确认、取件 |
| **运维** | 校区现场运维人员 | 一体机、打印机、本机设置 | 每日轻量巡检；接受管理侧派单到场处理 |
| **学校管理侧** | 学校信息化 / 后台管理员 | **管理网站（Cloud Admin）** | 监控在线与任务；发激活码；配置与启停；派单给运维 |
| **开发方** | 交付 / 研发 | Cloud 主机、发版、缺陷修复 | 底座可用、发安装包、修 bug；不替代学校日常值守 |

管理网站由**学校管理侧**日常使用，不是留给开发方代看的后台。

---

## 2. 协作关系（推荐）

```text
用户 ──使用──► 一体机 / 手机
                 ▲
运维 ──到场处理 / 日检──┘
                 ▲ 派单
学校管理侧 ──监控管理网站──► 发现问题则派运维
                 │
                 ▼ 无法定位或疑似缺陷
              开发方
```

| 原则 | 说明 |
|------|------|
| 监控在管理侧 | 在线、失败任务、告警以管理网站为准，不必靠人肉整天盯机房 |
| 到场在运维 | 换纸、查网、重启一体机、测打印等须人到现场 |
| 日检保持很轻 | 运维每天一次确认「能出码、打印机正常」即可 |
| 开发方处理 | 入口宕机、版本发布或确认属于软件缺陷的问题；不负责「默认打印机未设置」等现场配置问题 |

## 3. 各角色：做什么、什么时候做

### 3.1 用户

| 时机 | 事项 |
|------|------|
| 需要打印时 | 扫码 → 选入口 → 上传或按第三方提示操作 → 在一体机确认 → 取件 |
| 遇到占用 / 过期 | 等待或请现场刷新二维码后再扫 |
| 打不出 / 缺纸提示 | 告知运维或管理侧，勿自行改本机设置 |

用户**不负责**管理网站、激活、加打印机。

### 3.2 运维（现场）

| 时机 | 事项 |
|------|------|
| **每日一次（轻量巡检）** | 一体机开机或已开机；大屏可出码；打印机有纸、无明显故障灯 |
| **接到管理侧派单时** | 按派单到场：查网、重启一体机、刷新二维码、查默认打印机与耗材、测试打印；处理结果回告管理侧 |
| **新机 / 换机（在管理侧指导下）** | 本机填写云端地址与激活码；添加打印机并设默认、测试打印 |
| **升级窗口** | 按通知安装一体机升级包；确认可出码后回告管理侧 |
| **升级开发方前** | 完成第 5 章自查；仍失败再由管理侧升级开发方 |

运维**不负责**改管理网站全局配置、三方密钥、业务配置。

### 3.3 学校管理侧（信息化 / Admin）

| 时机 | 事项 |
|------|------|
| **日常（可随时）** | 打开管理网站：看节点是否在线、告警与失败任务；异常则**派运维**并说明校区与现象 |
| **新一体机上线** | 「节点信息」发激活码；告知云端地址；确认节点在线；核对「打印机信息」；在「打印任务」确认试打完成 |
| **暂停某校区** | 停用对应节点，并通知运维停止使用 |
| **人员交接** | 交接 Admin 账号与密码；更新「运维人员」联系人并绑定节点 |
| **三方入口** | 在「三方接入」启停 Provider、轮换密钥，并将目标 Edge 绑定到该 Provider；与对接方同步变更 |
| **业务制度变更** | 在「业务配置」调整上传限制等，并记录变更 |
| **收到开发方升级通知** | 通知各校区运维执行；升级后在管理网站核对在线与试打任务 |
| **现场无法解决** | 汇总节点名、时间、任务号、截图，升级开发方 |

首次交付后须修改默认管理员密码，并由管理侧自行保管。

### 3.4 开发方

| 时机 | 事项 |
|------|------|
| Cloud 入口或主机不可用 | 修复底座、域名、证书、发布入口 |
| 发版 / 出安装包 | 提供包、说明与窗口建议；不代替管理侧组织校区执行 |
| 确认属于产品缺陷 | 按缺陷流程修复并回归；管理侧协助复现信息 |
| 不接手的典型单 | 未激活、未设默认打印机、缺纸、校内网络不通、密码遗忘未走交接 |

---

## 4. 派单与升级（简表）

| 情况 | 谁先处理 | 下一步 |
|------|----------|--------|
| 单校区无码 / 打不出 | 管理侧发现或用户报修 → **派运维** | 运维自查后仍不行 → 管理侧升级开发方 |
| 多校区同时异常 | 管理侧判断 | 优先升级开发方（可能是 Cloud 侧） |
| 管理网站无法打开 | 管理侧 | 直接升级开发方 |
| 用户不会用 | 指导用户按使用说明操作，或由运维协助 | 不升级开发方 |

---

## 5. 运维到场自查（报开发方前）

1. 一体机是否进入飞印大屏。  
2. 一体机是否能上网。  
3. 打印机是否开机、有纸。  
4. 本机设置中云端是否已连接、是否已设默认打印机。  
5. 刷新二维码后是否仍失败。

## 7. 学校侧日常巡检与到场处置

### 7.1 日常与每周巡检

| 频度 | 现场责任人动作 |
|------|----------------|
| 上班前 | 确认一体机已开机并显示二维码或“准备就绪”；确认打印机开机、有纸、无缺墨或卡纸告警 |
| 下班 | 按学校交接要求关机或休眠；不卸载 Edge，不修改云端地址 |
| 每周 | 核对一体机时间、打印耗材；用手机扫码确认能打开入口页（不要求每次实际出纸） |

### 7.2 到场排障顺序

1. 记录校区、终端位置、开始时间、二维码或一体机屏幕现象。
2. 检查一体机网络；无二维码时可重启一体机，等待其重新建立云端连接。
3. 检查打印机开机、纸张、耗材、卡纸和网络；有预览但无出纸时，在本机设置中核对默认 IPP 打印机并执行测试打印。
4. 扫码打不开或提示 404 时，刷新二维码后重试，并保留手机地址栏完整截图。
5. 将处理结果、截图和任务号（如有）回告学校管理侧，由管理侧在 Cloud 管理端复核节点和任务状态。

### 7.3 升级与升级开发方

- 单校区连续离线约 15 分钟、完成上述自查仍不能恢复，或升级安装失败：学校管理侧收集校区、节点名、时间、现象、手机完整网址和屏幕截图后升级开发方。
- 多校区同时异常、Cloud 管理端不可访问，或疑似 Cloud 入口问题：学校管理侧直接升级开发方，并暂停扩大现场变更。
- 怀疑中毒、误删软件或不明程序影响一体机时，先停止该机对外使用并立即报障；不要自行重装、清理或替换软件。

### 7.4 禁止动作

- 不得把 Edge 本机管理页暴露到公网。
- 不得擅自改 `cloud.base_url`、全局业务配置、第三方密钥或 Provider 配置。
- 不得向公开群发送管理员密码、激活码、HMAC 密钥或演示凭证。
- 不得执行删除数据卷、清空服务器数据或类似高风险操作。
